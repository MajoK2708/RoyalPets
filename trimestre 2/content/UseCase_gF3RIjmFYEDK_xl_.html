Use Case Note
■ Workflow (Flujo de trabajo)
    • // Write down briefly how user perform the work
    • Usuario ingresa con correo y contraseña
    • Presiona “Iniciar sesión”.
    • Sistema valida credenciales.
    • Si son correctas, redirige al dashboard.
■ Business Logic (Logica de negocio)
    • // Write down what user expect the system to react upon certain condition (e.g. low inventory alert level)
    • Validar que el usuario exista.
    • Verificar contraseña encriptada.
    • Verificar que el usuario esté activo.
    • Si falla: mostrar mensaje de error.
    • Si el usuario está inactivo: bloquear acceso.
■ Decisions(Decisiones)
    • // Write down the decisions made during the meeting (e.g. Must allow accessing from mobile devices)
    • Se usará autenticación con contraseña encriptada.
    • Se bloqueará el usuario tras 3 intentos fallidos.
    • Se manejarán roles (admin, veterinario, cliente).
■ Follow-up(Seguimiento)
    • // Write down the items that should follow-up in the coming meeting
    • Definir política de recuperación de contraseña.
    • Definir duración de sesión.

admin/cliente/veterinario
Steps
1. Los usuarios ingresan al aplicativo web
2. Los usuarios acceden a la pantalla de inicio de sesión
3. El sistema muestra el formulario con los campos de correo y contraseña
4. Los usuarios ingresan el correo
5. Los usuarios ingresan la contraseña
6. Los usuarios apretan el botón "Iniciar sesión"
7. El sistema valida que los campos solicitados no esten vacíos
8. if (los campos no están vacíos)
    8.1. El sistema valida en la base de datos la existencia del correo ingresado.
    8.2. El sistema compara la contraseña ingresada con la almacenada.
    8.3. El sistema identifica el rol del usuario.
9. else
    9.1. El sistema muestra mensaje: "Usuario inactivo".
    9.2. El sistema muestra mensaje: "Contraseña incorrecta".
    9.3. El sistema muestra mensaje: "Correo no registrado".
    9.4. El sistema muestra mensaje: "Debe completar todos los campos".
   end if
