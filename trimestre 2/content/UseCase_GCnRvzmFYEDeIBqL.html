Use Case Note
■ Workflow
    • // Write down briefly how user perform the work
    • Usuario accede al módulo de servicios.
    • Selecciona una cita existente.
    • Hace clic en “Agregar servicio adicional”.
    • Ingresa los datos del servicio.
    • Guarda la información.
■ Business Logic
    • // Write down what user expect the system to react upon certain condition (e.g. low inventory alert level)
    • El sistema permite agregar múltiples servicios a una cita.
    • Valida que los campos sean obligatorios.
    • Actualiza el costo total automáticamente.
    • Guarda el servicio en la base de datos.
■ Decisions
    • // Write down the decisions made during the meeting (e.g. Must allow accessing from mobile devices)
    • Se permitirá editar y eliminar servicios adicionales.
    • Se calculará automáticamente el precio total.
    • Interfaz simple y rápida para el registro.
■ Follow-up
    • // Write down the items that should follow-up in the coming meeting
    • Agregar historial de servicios.
    • Validar reportes de servicios adicionales.

Scenario
Steps
1. Los actores ingresa al aplicativo web
2. Los actores selecciona una cita/agendamiento.
3. Presiona “Agregar servicio adicional”.
4. if
    4.1. El usuario ingresa los datos del servicio adicional.
    4.2. Selecciona el tipo de servicio.
    4.3. Ingresa costo y descripción (si aplica).
    4.4. Presiona “Guardar”.
    4.5. El sistema valida los datos ingresados.
    4.6. El sistema registra el servicio adicional en la base de datos.
    4.7. El sistema actualiza el costo total de la cita.
5. else El sistema muestra mensaje de error en los datos ingresados.
   end if
