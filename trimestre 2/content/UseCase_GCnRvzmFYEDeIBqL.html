El cliente ingresa al módulo de servicios adicionales, registra un nuevo servicio para su mascota y el sistema valida y almacena la información correctamente.

Use Case Note
■ Workflow
    • // Write down briefly how user perform the work
    • Los actores inician sesión en el sistema.
    • Acceden al módulo de servicios adicionales.
    • Registran un nuevo servicio adicional.
    • El sistema valida y guarda la información.
■ Business Logic
    • // Write down what user expect the system to react upon certain condition (e.g. low inventory alert level)
    • El servicio adicional debe estar asociado a una mascota previamente registrada.
    • No se puede registrar un servicio sin datos obligatorios (tipo de servicio, fecha, mascota).
    • El sistema debe validar disponibilidad si el servicio requiere agenda.
    • Los servicios quedan registrados con estado activo por defecto.
■ Decisions
    • // Write down the decisions made during the meeting (e.g. Must allow accessing from mobile devices)
    • Se permite que el cliente registre servicios sin intervención del veterinario solo para baño y peluquería.
    • Los servicios adicionales deben requerir agendamiento.
    • Se validará que la mascota pertenezca al cliente autenticado.
■ Follow-up
    • // Write down the items that should follow-up in the coming meeting
    • Implementar notificaciones de confirmación del servicio.
    • Permitir valoración del servicio por parte del cliente.

Scenario
Steps
1. El actor accede al sistema mediante sus credenciales.
2. El sistema valida sus credenciales en el sistema.
3. El actor ingresa al módulo “Servicios adicionales”.
4. El sistema muestra el listado de servicios adicionales registrados.
5. El actor selecciona la opción “Registrar servicio adicional”.
6. El sistema muestra el formulario de registro.
7. El actor ingresa la información requerida (tipo de servicio, mascota, fecha, observaciones).
8. if El actor completa correctamente los datos requeridos.
    8.1. 8.2. El sistema valida la información ingresada.
    8.2. 8.3. El sistema verifica que la mascota esté registrada y pertenezca al actor.
    8.3. 8.4. El sistema registra el servicio adicional en la base de datos.
    8.4. 8.5. El sistema muestra un mensaje: "Servicio adicional registrado exitosamente".
    8.5. 8.6. El actor puede visualizar el servicio en el listado.
9. else
    9.1. 9.1. El sistema muestra un mensaje: "Error en el registro del servicio. Verifique los datos ingresados".
    9.2. 9.2. El actor corrige la información.
    9.3. 9.3. El actor intenta nuevamente el registro.
   end if
