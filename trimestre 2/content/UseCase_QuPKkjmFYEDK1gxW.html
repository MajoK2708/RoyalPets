Use Case Note
■ Workflow
    • // Write down briefly how user perform the work
    • El usuario selecciona un recurso y un horario.
    • El sistema revisa la disponibilidad.
    • Se confirma o se indica que no está disponible.
■ Business Logic
    • // Write down what user expect the system to react upon certain condition (e.g. low inventory alert level)
    • La disponibilidad se consulta en tiempo real contra la base de datos.
    • Se bloquea la opción de seleccionar recursos ya ocupados.
    • El sistema puede considerar reglas de prioridad o restricciones de agenda.
■ Decisions
    • // Write down the decisions made during the meeting (e.g. Must allow accessing from mobile devices)
    • Si el recurso no está disponible, el sistema sugiere alternativas.
    • Solo se permite reservar recursos disponibles.
    • La validación puede ser obligatoria antes de registrar o confirmar cualquier acción.
■ Follow-up
    • // Write down the items that should follow-up in the coming meeting
    • Registrar la validación para auditoría.
    • Integrar alertas si un recurso se libera o cambia de disponibilidad.
    • Reutilizar este caso de uso en todos los procesos que impliquen reserva de recursos.

Scenario
Steps
1. El usuario selecciona un recurso (cita, servicio, sala, etc.) y el horario deseado.
2. El sistema recibe la solicitud y consulta la base de datos sobre disponibilidad.
3. if El recurso está disponible en la fecha y hora seleccionadas.
    3.1. El sistema marca el recurso como disponible para el usuario.
    3.2. El usuario puede continuar con el registro o confirmación del recurso.
    3.3. El sistema bloquea temporalmente el recurso mientras se completa la acción.
4. else
    4.1. El sistema muestra un mensaje: "Recurso no disponible en la fecha/hora seleccionada".
    4.2. El usuario puede seleccionar otra fecha, horario o recurso.
    4.3. El sistema vuelve a validar la nueva selección.
   end if
